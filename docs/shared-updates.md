# Общая подписка на изменения

Backend предоставляет `updates.v1.UpdatesService/SubscribeUpdates`.
Запрос пустой, участник определяется по cookie-сессии. Анонимный вход запрещён.
Подписка не зависит от режима кабинета: `UserID` волонтёра и координатора общий.

## Контракт

| `kind` | Значение |
| --- | --- |
| `UPDATE_KIND_READY` | Соединение установлено. Нужно перечитать отображаемые данные, включая историю открытого чата. |
| `UPDATE_KIND_CHANGED` | Связанные с участником данные изменились. Нужно обновить соответствующие представления. |
| `UPDATE_KIND_HEARTBEAT` | Соединение живо. Перечитывать данные не требуется. |

Стрим передаёт только сигнал обновления, без ФИО, контактов, идентификаторов чужих объектов и текста сообщений.
Данные и сообщения клиент читает существующими RPC с актуальными проверками доступа и границы истории чата.
Например, после отмены участия уведомление не даёт права читать переписку.

На фронте соединение открывается после входа или восстановления авторизованной сессии,
один раз на вкладку. Переходы между страницами и переключение режима кабинета не требуют нового соединения.
При выходе клиент закрывает подписку. После обрыва переподключается и обрабатывает `READY` как полную
синхронизацию видимых данных. Набираемый текст и редактируемые формы при этом сохраняются.

Фронт использует общую подписку также для открытого чата. Отдельный RPC подписки чата сохранён
на backend для совместимости. Каждый `READY`, включая первый, запускает синхронизацию:
данные могли измениться между начальной загрузкой страницы и установлением соединения.
Сигналы объединяются в окно 300 мс; постоянный поток изменений не откладывает обновление бесконечно.
Выход отменяет текущее соединение и отложенный сигнал. Завершение старой подписки не меняет
состояние подписки нового входа.

## Реализация

- `api/rpc/updates`: определение изменяющих RPC по сгенерированным Procedure-константам, serde и уведомление
  после успешного завершения вызова. Транзакция репозитория к этому моменту уже завершена.
- `app/service/get-update-recipients`: определение связанных участников через репозитории агрегатов.
  Учитываются обе стороны сотрудничества, участники мероприятия, владелец поощрения и покупатель.
- `app/service/subscribe-updates`: повторная проверка существования, пользователя и срока cookie-сессии.
- `pkg/updates`: один общий Hub процесса с отдельными подписками пользователей. Interceptor находится в
  `pkg/updates/interceptor`. Сервисы app не вызывают другие сервисы.
- Проверки авторизации, состава получателей и связи агрегатов остаются вне SQL.

Неуспешный RPC не отправляет уведомления. Ошибка определения получателей после уже успешной записи
не превращает сохранённую операцию в ошибку: Hub отправляет всем подключениям только обезличенный сигнал
перечитать данные. Содержимое объектов по-прежнему проверяется обычными RPC.

У каждого подключения очередь на один сигнал. Повторные сигналы объединяются; сообщения чата в этой
очереди не хранятся. Поэтому при всплеске активности память не растёт вместе с числом изменений.
Отправка ограничена пятью секундами; медленный клиент не блокирует остальных.
Heartbeat отправляется каждые десять секунд и проверяет сессию даже при отсутствии изменений.
Закрытие сессии также будит её подписки, после чего поток завершается с `Unauthenticated`.
Для Nginx устанавливается `X-Accel-Buffering: no`.

Решение рассчитано на один процесс backend, как текущий Compose. При нескольких экземплярах потребуется
общий источник уведомлений. Прямые изменения БД вне RPC не публикуются в Hub; восстановление состояния
после разрыва обеспечивается перечитыванием данных, а не журналом доставки уведомлений.
Redis, брокер, новые таблицы и миграции не требуются.

## Проверки

`cd frontend && pnpm test` проверяет перенаправления при существующей сессии и жизненный цикл
общего стрима: начальную синхронизацию, повторный вход, отмену старого соединения и частые изменения.

`go test -tags=e2e ./tests/e2e/rpc -count=1` запускает приложение, PostgreSQL и Nginx в тестовом окружении.
В `tests/e2e/rpc/updates_test.go` проверяются:

- Одна подписка обслуживает изменения сотрудничества, заявок и сообщений для двух пользователей.
- Уведомления проходят через настоящий Nginx с включённой буферизацией.
- Без авторизации, с анонимной, поддельной и закрытой cookie доступ запрещён.
- Посторонний участник не получает уведомления о чужом чате; неуспешная операция не публикуется.
- Отзыв участия закрывает чтение чата, несмотря на полученное уведомление.
- Выход завершает открытую подписку; истечение сессии обнаруживается и без активности.
- Закрытие одной вкладки не отключает другую подписку того же пользователя.
- Повторное соединение получает `READY`, а сообщения, отправленные без подписки, доступны в PostgreSQL.

Полный набор проверяет успешные вызовы всех 60 RPC. Сценарии общего стрима дополнительно прошли с `go test -race`.
Линтер запускается с тегами `integration,e2e` и завершается без замечаний.
